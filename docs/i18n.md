# Interface translations

Every user-visible string lives in `locales/<code>.toml`. The files are
compiled into the binary, so packages do not install translation files.
English (`en.toml`) is the base catalog and the fallback for a key another
language does not provide. Shipped languages: English, German, French,
Simplified Chinese.

`cargo test` checks that every catalog has the same keys and the same
`{placeholders}`, and that every key used in `src/` is defined and used.

## Adding a string

1. Add the key to `locales/en.toml` and to every other catalog. Keep the
   placeholders identical (`{error}`, `{count}`, …).
2. Look the key up from Rust with a string literal:
   - `tr!("settings.region")` when the text is used once and then thrown
     away (command-line output, a toast, an error returned to the caller).
   - `phrase!("install.preparing")` when the text stays on screen and must
     follow a language change. Arguments that are themselves phrases are
     rendered again too; numbers, paths and error text are stored as-is.
3. In a Relm4 `view!`, put `#[watch]` on `set_label` / `set_tooltip_text`
   that call `tr!`. The main window re-renders its child components when the
   language changes, and a watch reads the catalog again.
4. For a widget built by hand (a menu, a dialog), register a refresh with
   `Bindings::watch` in `src/ui/text.rs` and keep the `Bindings` alive as
   long as the widget. `text::retain` stores them on the widget.

Do not rebuild the window to apply a language. `i18n::select` notifies the
registered closures; the window, its page, scroll positions and running
tasks stay as they are.

## Adding a language

1. Copy `locales/en.toml` to `locales/<code>.toml` and translate the values,
   including `meta.name` (the language's own name, shown in the menu).
2. Add a flag PNG next to the others in `locales/flags/` (rendered from the
   SVG beside it).
3. Register the catalog in the `CATALOGS` list in `src/i18n.rs`.

The gear menu lists the new language on the next start. No other call site
needs to change.

## What does not switch live

The optional login window is a separate program. It receives its title and
button text through the environment when it starts, and an already open
login window keeps that language. The next login uses the new one. Toasts
already on screen stay in the language they were created in.
