# hearthstone-linux-gui v0.2.3

Patch release focused on AppImage host compatibility and a packaging baseline
that works on old and new Linux distributions.

## Highlights

- **Login and game launch on Fedora/Bazzite (and similar hosts):** AppImage
  child processes no longer inherit the AppImage's bundled glibc/GLib. The
  Login button opens the system browser again instead of silently waiting, and
  short game exits surface an exit code plus log paths (#22, #23).
- **Login URL always visible:** while a login is pending the full URL is shown
  with a Copy button so you can paste it if no browser opens.
- **AppImage rebuilt without bundled glibc:** builds now use AlmaLinux 9
  (glibc 2.34) and linuxdeploy; only GTK 4 / libadwaita / GLib are bundled.
  Native deb / rpm / pacman packages share the same glibc floor (#24).
- **Packaging CI:** multi-distro smoke tests, `--print-child-env` checks, and
  fixes for SIGPIPE / ETXTBSY / headless GSK so Packaging CI stays green.

## Downloads

- **AppImage** — portable x86_64; needs glibc ≥ 2.34 (RHEL/Alma/Rocky 9,
  Ubuntu 22.04, Debian 12, Fedora 35+, and newer).
- **DEB / RPM / Pacman** — system GTK 4 (≥ 4.0) and libadwaita (≥ 1.0); same
  glibc floor.
- **Nix** — `nix build github:DawnMagnet/hearthstone-linux-gui/v0.2.3`
